# Updating Armor

A guide for converting GeckoLib 3 armor to AzureLib on Forge 1.7.10.

| GeckoLib 3                                          | AzureLib                                                                                 |
|-----------------------------------------------------|------------------------------------------------------------------------------------------|
| `GeoArmorItem` + `IAnimatable` + `AnimationFactory` | A plain `ItemArmor` holding a Dispatcher                                                 |
| `registerControllers` and predicates on the item    | An `AzItemAnimator` class                                                                |
| `AnimatedGeoModel`                                  | Model and texture go in `AzArmorRendererConfig`, the animation file goes in the Animator |
| `headBone`, `bodyBone`, ... fields on the renderer  | An `AzDefaultArmorBoneProvider` subclass                                                 |
| `GeoArmorRenderer.registerArmorRenderer`            | `AzArmorRendererRegistry.register`                                                       |

## Armor Item Class

<CodeTabs>

```java !!tabs GeckoLib 3
public class ExampleArmor extends GeoArmorItem implements IAnimatable {
    private AnimationFactory factory = new AnimationFactory(this);

    public ExampleArmor(ArmorMaterial material, int renderIndex, int armorType) {
        super(material, renderIndex, armorType);
    }

    private <P extends IAnimatable> PlayState predicate(AnimationEvent<P> event) {
        EntityLivingBase livingEntity = event.getExtraDataOfType(EntityLivingBase.class).get(0);
        event.getController().setAnimation(new AnimationBuilder().addAnimation("idle", true));
        return isFullSetWorn(livingEntity) ? PlayState.CONTINUE : PlayState.STOP;
    }

    public boolean isFullSetWorn(EntityLivingBase entity) {
        for (int i = 1; i < 5; i++) {
            if (entity.getEquipmentInSlot(i) == null || !(entity.getEquipmentInSlot(i).getItem() instanceof ExampleArmor)) {
                return false;
            }
        }
        return true;
    }

    @Override
    public void registerControllers(AnimationData data) {
        data.addAnimationController(new AnimationController<>(this, "base_controller", 20, this::predicate));
    }

    @Override
    public AnimationFactory getFactory() {
        return this.factory;
    }
}
```

```java !!tabs AzureLib
public class ExampleArmor extends ItemArmor {
    // This is your class where you will setup the AzCommands/Animations you wish to play
    private final ExampleArmorDispatcher dispatcher;

    /**
     * @param armorType 0 helmet, 1 chestplate, 2 leggings, 3 boots
     */
    public ExampleArmor(ArmorMaterial material, int renderIndex, int armorType) {
        super(material, renderIndex, armorType);
        this.setMaxStackSize(1);
        // Create the instance of the class here to use later.
        this.dispatcher = new ExampleArmorDispatcher();
    }

    // Forge's per-tick hook for worn armor
    @Override
    public void onArmorTick(World world, EntityPlayer player, ItemStack itemStack) {
        // This is where you now trigger an animation to play.
        // Only sending it while the full set is worn replaces returning PlayState.STOP.
        if (!world.isRemote && isFullSetWorn(player)) {
            dispatcher.idle(player, itemStack);
        }
    }

    public boolean isFullSetWorn(EntityLivingBase entity) {
        for (int i = 1; i < 5; i++) {
            if (entity.getEquipmentInSlot(i) == null || !(entity.getEquipmentInSlot(i).getItem() instanceof ExampleArmor)) {
                return false;
            }
        }
        return true;
    }
}
```

</CodeTabs>

As you can see here, you no longer extend `GeoArmorItem`, implement `IAnimatable`, or register your controllers in the item. Your armor is a normal `ItemArmor` again. All that is needed now is a Dispatcher, which we will cover below.

<Callout variant="info">
    `onArmorTick` only runs for players. If you need armor animations on other mobs wearing it, send the command from that mob's own update logic instead.
</Callout>

<CodeTabs>

```java !!tabs GeckoLib 3
    // In ExampleArmor
    @Override
    public void registerControllers(AnimationData data) {
        data.addAnimationController(new AnimationController<>(this, "base_controller", 20, this::predicate));
    }

    // In ExampleArmorModel
    @Override
    public ResourceLocation getAnimationFileLocation(ExampleArmor animatable) {
        return new ResourceLocation(YOUR_MOD_ID, "animations/examplearmor.animation.json");
    }
```

```java !!tabs AzureLib
public class ExampleArmorAnimator extends AzItemAnimator {
    private static final ResourceLocation ANIMATIONS = new ResourceLocation(
        YOUR_MOD_ID,
        "animations/item/examplearmor.animation.json"
    );

    @Override
    public void registerControllers(AzAnimationControllerContainer<ItemStack> animationControllerContainer) {
        animationControllerContainer.add(
            AzAnimationController.builder(this, "base_controller")
                .build()
        );
    }

    @Override
    public @Nonnull ResourceLocation getAnimationLocation(ItemStack animatable) {
        return ANIMATIONS;
    }
}
```

</CodeTabs>

<Callout variant="info">
    It is recommended to create a dedicated class for your animation triggers, as AzureLib works by sending animation commands rather than running a predicate every frame. This is the Dispatcher created in the armor class above:
</Callout>
```java
public class ExampleArmorDispatcher {
    private static final AzCommand IDLE_COMMAND = AzCommand.create(
        "base_controller",
        "idle"
    );

    public void idle(Entity entity, ItemStack itemStack) {
        IDLE_COMMAND.sendForItem(entity, itemStack);
    }
}
```

## Rendering

<Callout variant="info">
    See [here](../misc/rendering/azrenderer_config#azarmorrendererconfig) for a more indepth example
</Callout>

<CodeTabs>

```java !!tabs GeckoLib 3
public class ExampleArmorModel extends AnimatedGeoModel<ExampleArmor> {
    @Override
    public ResourceLocation getModelLocation(ExampleArmor object) {
        return new ResourceLocation(YOUR_MOD_ID, "geo/examplearmor.geo.json");
    }

    @Override
    public ResourceLocation getTextureLocation(ExampleArmor object) {
        return new ResourceLocation(YOUR_MOD_ID, "textures/item/examplearmor.png");
    }

    @Override
    public ResourceLocation getAnimationFileLocation(ExampleArmor animatable) {
        return new ResourceLocation(YOUR_MOD_ID, "animations/examplearmor.animation.json");
    }
}

public class ExampleArmorRenderer extends GeoArmorRenderer<ExampleArmor> {
    public ExampleArmorRenderer() {
        super(new ExampleArmorModel());
    }
}
```

```java !!tabs AzureLib
public class ExampleArmorRenderer extends AzArmorRenderer {
    private static final ResourceLocation GEO = new ResourceLocation(
        YOUR_MOD_ID,
        "geo/item/examplearmor.geo.json"
    );

    private static final ResourceLocation TEX = new ResourceLocation(
        YOUR_MOD_ID,
        "textures/item/examplearmor.png"
    );

    public ExampleArmorRenderer() {
        super(
            AzArmorRendererConfig.builder(GEO, TEX)
                .setAnimatorProvider(ExampleArmorAnimator::new)
                .build()
        );
    }
}
```

</CodeTabs>

The model class is gone. This is where you now register the ResourceLocation model and texture of your armor, and where you register your ExampleArmorAnimator.

### Custom bone names

If your GeckoLib 3 renderer changed the `headBone`, `bodyBone`, `rightLegBone` (and so on) fields because your Blockbench bones use different names, move that into a bone provider and pass it to the config with `setBoneProvider`. If you were using the default armor template bone names, you can skip this.

<CodeTabs>

```java !!tabs GeckoLib 3
    public ExampleArmorRenderer() {
        super(new ExampleArmorModel());

        this.headBone = "helmet";
        this.bodyBone = "chestplate";
        this.rightArmBone = "rightArm";
        this.leftArmBone = "leftArm";
        this.rightLegBone = "rightLeg";
        this.leftLegBone = "leftLeg";
        this.rightBootBone = "rightBoot";
        this.leftBootBone = "leftBoot";
    }
```

```java !!tabs AzureLib
public class ExampleArmorBoneProvider extends AzDefaultArmorBoneProvider {
    @Override
    public AzBone getRightLegBone(AzBakedModel model) {
        return model.getBone("rightLeg").orElse(null);
    }

    @Override
    public AzBone getLeftLegBone(AzBakedModel model) {
        return model.getBone("leftLeg").orElse(null);
    }

    @Override
    public AzBone getRightBootBone(AzBakedModel model) {
        return model.getBone("rightBoot").orElse(null);
    }

    @Override
    public AzBone getLeftBootBone(AzBakedModel model) {
        return model.getBone("leftBoot").orElse(null);
    }

    // Override the head, body and arm getters the same way for those bones
}

// Then in ExampleArmorRenderer:
AzArmorRendererConfig.builder(GEO, TEX)
    .setAnimatorProvider(ExampleArmorAnimator::new)
    .setBoneProvider(new ExampleArmorBoneProvider())
    .build()
```

</CodeTabs>

## Registering

<CodeTabs>

```java !!tabs GeckoLib 3
@SideOnly(Side.CLIENT)
public static void registerRenderers(FMLInitializationEvent event) {
    GeoArmorRenderer.registerArmorRenderer(ExampleArmor.class, new ExampleArmorRenderer());
}
```

```java !!tabs AzureLib
// In your ClientProxy#init
@Override
public void init() {
    AzArmorRendererRegistry.register(
        ExampleArmorRenderer::new,
        ItemRegistry.YOUR_ARMOR_HELMET,
        ItemRegistry.YOUR_ARMOR_CHESTPLATE,
        ItemRegistry.YOUR_ARMOR_LEGGINGS,
        ItemRegistry.YOUR_ARMOR_BOOTS
    );
}
```

</CodeTabs>

Now simply call `AzArmorRendererRegistry#register()` in your client proxy's init. GeckoLib 3 registered by armor class; AzureLib registers by the item instances, so list every piece.

## Registering your Armor for proper animation triggering

To ensure trigger animations work properly, you will need to also call `AzIdentityRegistry#register()` during `FMLInitializationEvent` in your common code (so it runs on both the client and the server) like so:

```java
AzIdentityRegistry.register(
    ItemRegistry.YOUR_ARMOR_HELMET,
    ItemRegistry.YOUR_ARMOR_CHESTPLATE,
    ItemRegistry.YOUR_ARMOR_LEGGINGS,
    ItemRegistry.YOUR_ARMOR_BOOTS,
    ...
);
```
