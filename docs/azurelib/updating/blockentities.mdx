# Updating Block Entities

A guide for converting GeckoLib 3 tile entities to AzureLib on Forge 1.12.2.

| GeckoLib 3                                              | AzureLib                                                                                       |
|---------------------------------------------------------|------------------------------------------------------------------------------------------------|
| `IAnimatable` and `AnimationFactory` on the tile entity | Removed. The tile entity holds a Dispatcher instead                                            |
| `registerControllers` and predicates on the tile entity | An `AzBlockAnimator` class                                                                     |
| `AnimatedGeoModel`                                      | Model and texture go in `AzBlockEntityRendererConfig`, the animation file goes in the Animator |
| `GeoBlockRenderer`                                      | `AzBlockEntityRenderer`                                                                        |

Your block class (`ITileEntityProvider`, `getRenderType()` returning `EnumBlockRenderType.ENTITYBLOCK_ANIMATED`, and so on) does not need to change.

## Tile Entity Class

<CodeTabs>

```java !!tabs GeckoLib 3
public class ExampleTileEntity extends TileEntity implements IAnimatable {
    private final AnimationFactory factory = new AnimationFactory(this);

    private <E extends TileEntity & IAnimatable> PlayState predicate(AnimationEvent<E> event) {
        event.getController().transitionLengthTicks = 0;
        event.getController().setAnimation(new AnimationBuilder().addAnimation("spinning", true));
        return PlayState.CONTINUE;
    }

    @Override
    public void registerControllers(AnimationData data) {
        data.addAnimationController(new AnimationController<>(this, "base_controller", 0, this::predicate));
    }

    @Override
    public AnimationFactory getFactory() {
        return factory;
    }
}
```

```java !!tabs AzureLib
public class ExampleTileEntity extends TileEntity implements ITickable {
    // This is your class where you will setup the AzCommands/Animations you wish to play
    public final ExampleTileEntityDispatcher dispatcher;

    public ExampleTileEntity() {
        // Create the instance of the class here to use later.
        this.dispatcher = new ExampleTileEntityDispatcher(this);
    }

    @Override
    public void update() {
        if (this.world != null && this.world.isRemote) {
            // This is where you now trigger an animation to play
            this.dispatcher.spin();
        }
    }
}
```

</CodeTabs>

As you can see here, you no longer need to implement `IAnimatable`, keep an `AnimationFactory`, or register your controllers in the tile entity. Instead the tile entity implements `ITickable` so it has somewhere to send its animation from. All that is needed now is a Dispatcher, which we will cover below.

## Animations

<Callout variant="info">
    See [here](../misc/animating/azcommands_101) for more indepth info about AzCommands
</Callout>

<CodeTabs>

```java !!tabs GeckoLib 3
    // In ExampleTileEntity
    @Override
    public void registerControllers(AnimationData data) {
        data.addAnimationController(new AnimationController<>(this, "base_controller", 0, this::predicate));
    }

    // In ExampleTileModel
    @Override
    public ResourceLocation getAnimationFileLocation(ExampleTileEntity animatable) {
        return new ResourceLocation(YOUR_MOD_ID, "animations/exampletile.animation.json");
    }
```

```java !!tabs AzureLib
public class ExampleTileEntityAnimator extends AzBlockAnimator<ExampleTileEntity> {
    private static final ResourceLocation ANIMATIONS = new ResourceLocation(
        YOUR_MOD_ID,
        "animations/block/exampletile.animation.json"
    );

    public ExampleTileEntityAnimator() {
        super(AzAnimatorConfig.defaultConfig());
    }

    @Override
    public void registerControllers(AzAnimationControllerContainer<ExampleTileEntity> animationControllerContainer) {
        animationControllerContainer.add(
            AzAnimationController.builder(this, "base_controller")
                // Replaces event.getController().transitionLengthTicks = 0
                .setTransitionLength(0)
                .build()
        );
    }

    @Override
    public @Nonnull ResourceLocation getAnimationLocation(ExampleTileEntity animatable) {
        return ANIMATIONS;
    }
}
```

</CodeTabs>

<Callout variant="info">
    It is recommended to create a dedicated class for your animation triggers, as AzureLib works by sending animation commands rather than running a predicate every frame. This is the Dispatcher created in the tile entity class above:
</Callout>
```java
public class ExampleTileEntityDispatcher {
    private static final AzCommand SPINNING_COMMAND = AzCommand.create(
        "base_controller",
        "spinning",
        AzPlayBehaviors.LOOP
    );

    private final ExampleTileEntity tileEntity;

    public ExampleTileEntityDispatcher(ExampleTileEntity tileEntity) {
        this.tileEntity = tileEntity;
    }

    public void spin() {
        SPINNING_COMMAND.sendForBlockEntity(tileEntity);
    }
}
```

## Rendering

<Callout variant="info">
    See [here](../misc/rendering/azrenderer_config#azblockentityrendererconfig) for a more indepth example
</Callout>

<CodeTabs>

```java !!tabs GeckoLib 3
public class ExampleTileModel extends AnimatedGeoModel<ExampleTileEntity> {
    @Override
    public ResourceLocation getAnimationFileLocation(ExampleTileEntity entity) {
        return new ResourceLocation(YOUR_MOD_ID, "animations/exampletile.animation.json");
    }

    @Override
    public ResourceLocation getModelLocation(ExampleTileEntity animatable) {
        return new ResourceLocation(YOUR_MOD_ID, "geo/exampletile.geo.json");
    }

    @Override
    public ResourceLocation getTextureLocation(ExampleTileEntity entity) {
        return new ResourceLocation(YOUR_MOD_ID, "textures/block/exampletile.png");
    }
}

public class ExampleTileRenderer extends GeoBlockRenderer<ExampleTileEntity> {
    public ExampleTileRenderer() {
        super(new ExampleTileModel());
    }
}
```

```java !!tabs AzureLib
public class ExampleTileRenderer extends AzBlockEntityRenderer<ExampleTileEntity> {
    private static final ResourceLocation GEO = new ResourceLocation(
        YOUR_MOD_ID,
        "geo/block/exampletile.geo.json"
    );

    private static final ResourceLocation TEX = new ResourceLocation(
        YOUR_MOD_ID,
        "textures/block/exampletile.png"
    );

    public ExampleTileRenderer() {
        super(
            AzBlockEntityRendererConfig.<ExampleTileEntity>builder(GEO, TEX)
                .setAnimatorProvider(ExampleTileEntityAnimator::new)
                .build()
        );
    }
}
```

</CodeTabs>

The model class is gone. This is where you now register the ResourceLocation model and texture of your block, and where you register your ExampleTileEntityAnimator.

## Animating the block's item (optional)

With GeckoLib 3 the block's `ItemBlock` was a normal static item. With AzureLib you can also render it with your animated model: give the `ItemBlock` an `AzItemAnimator` and an `AzItemRenderer` that point at the same model, texture and animation file.

```java
public class ExampleBlockItemAnimator extends AzItemAnimator {
    private static final ResourceLocation ANIMATIONS = new ResourceLocation(
        YOUR_MOD_ID,
        "animations/block/exampletile.animation.json"
    );

    public ExampleBlockItemAnimator() {
        super(AzAnimatorConfig.defaultConfig());
    }

    @Override
    public void registerControllers(AzAnimationControllerContainer<ItemStack> animationControllerContainer) {
        animationControllerContainer.add(
            AzAnimationController.builder(this, "base_controller").build()
        );
    }

    @Override
    public @Nonnull ResourceLocation getAnimationLocation(ItemStack animatable) {
        return ANIMATIONS;
    }
}

public class ExampleBlockItemRenderer extends AzItemRenderer {
    private static final ResourceLocation GEO = new ResourceLocation(YOUR_MOD_ID, "geo/block/exampletile.geo.json");
    private static final ResourceLocation TEX = new ResourceLocation(YOUR_MOD_ID, "textures/block/exampletile.png");

    public ExampleBlockItemRenderer() {
        super(
            AzItemRendererConfig.builder(GEO, TEX)
                .setAnimatorProvider(ExampleBlockItemAnimator::new)
                .build()
        );
    }
}
```

<Callout variant="info">
    The item model at `assets/YOUR_MOD_ID/models/item/<block name>.json` needs `"parent": "builtin/entity"`, and the display transforms are read from that file.
</Callout>

## Registering

Tile entity registration with `GameRegistry.registerTileEntity` doesn't change.

<CodeTabs>

```java !!tabs GeckoLib 3
@SideOnly(Side.CLIENT)
@Mod.EventHandler
public void registerRenderers(FMLPreInitializationEvent event) {
    ClientRegistry.bindTileEntitySpecialRenderer(ExampleTileEntity.class, new ExampleTileRenderer());
}
```

```java !!tabs AzureLib
// In your ClientProxy#init
@Override
public void init() {
    ClientRegistry.bindTileEntitySpecialRenderer(ExampleTileEntity.class, new ExampleTileRenderer());

    // Only needed if you want the block's item animated/rendered by AzureLib
    AzItemRendererRegistry.register(BlockRegistry.EXAMPLE_BLOCK_ITEM, ExampleBlockItemRenderer::new);
}
```

</CodeTabs>

If you render the block's item with AzureLib, also register it in `AzIdentityRegistry#register()` during `FMLInitializationEvent` in your common code (so it runs on both the client and the server):

```java
AzIdentityRegistry.register(BlockRegistry.EXAMPLE_BLOCK_ITEM, ...);
```
