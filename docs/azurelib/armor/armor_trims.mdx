# Armor Trims

AzureLib supports Minecraft's armor trim system through the `AzArmorTrimLayer` render layer. It draws the trim on your custom armor model using the trim's pattern and the trim material's colors.

<Callout variant="info">
    This page is for Minecraft 26.3 and later. Since 26.3, trims use paletted textures instead of the `armor_trims` atlas. If you're updating from 1.21.x, see [Updating from 1.21.x](#updating-from-121x).
</Callout>

## How Trim Textures Work

A trim texture is a **grayscale** image. Minecraft recolors it with each trim material's palette (gold, iron, diamond, ...) at runtime, so you only make the grayscale version. To mark a texture as recolorable, put a `.png.mcmeta` file next to it:

```json
{
    "palette": {
        "base_palette": "minecraft:trim_base"
    }
}
```

- `minecraft:trim_base` is vanilla's grayscale trim palette. Draw your trim with the same gray shades vanilla's trim textures use, so every shade maps to a material color.
- Trim materials from other mods work automatically, as long as they define their palette.
- **The trim texture must be the same size as your armor texture.** It's drawn with your armor model's own UVs, so it lines up with the armor texture pixel for pixel.

Texture ids in code are relative to `textures/` and have no `.png`: `yourmod:trims/your_armor_trim` means `assets/yourmod/textures/trims/your_armor_trim.png`.

## Implementation Approaches

### Approach 1: Single Texture for All Patterns

Uses one trim texture for every pattern, still colored by the trim material. Recommended when you don't have time to make a texture for every pattern.

#### Required Assets
```
src/main/resources/assets/yourmod/textures/trims/your_armor_trim.png
src/main/resources/assets/yourmod/textures/trims/your_armor_trim.png.mcmeta
```

#### Code Implementation
```java
public class ExampleArmorRenderer extends AzArmorRenderer {
    private static final Identifier GEO = Identifier.fromNamespaceAndPath(
        YOUR_MOD_ID,
        "geo/item/examplearmor.geo.json"
    );

    private static final Identifier TEX = Identifier.fromNamespaceAndPath(
        YOUR_MOD_ID,
        "textures/item/examplearmor.png"
    );

    public ExampleArmorRenderer() {
        super(AzArmorRendererConfig.builder(GEO, TEX)
            .addRenderLayer(new AzArmorTrimLayer(
                Identifier.fromNamespaceAndPath(YOUR_MOD_ID, "trims/your_armor_trim"),
                false  // supportPatterns = false for a single texture
            ))
            .build());
    }
}
```

### Approach 2: Per-Pattern Textures

Uses a separate texture for each trim pattern, like vanilla. This gives the best results but takes more work.

#### Required Assets

<Callout variant="info">
    See the [Minecraft Wiki](https://minecraft.wiki/w/Smithing_Template) for all vanilla patterns.
</Callout>

Make one texture per pattern, named `<base>_<pattern>`, each with the same `.png.mcmeta` shown above:
```
src/main/resources/assets/yourmod/textures/trims/your_armor_sentry.png
src/main/resources/assets/yourmod/textures/trims/your_armor_sentry.png.mcmeta
src/main/resources/assets/yourmod/textures/trims/your_armor_vex.png
src/main/resources/assets/yourmod/textures/trims/your_armor_vex.png.mcmeta
src/main/resources/assets/yourmod/textures/trims/your_armor_wild.png
src/main/resources/assets/yourmod/textures/trims/your_armor_wild.png.mcmeta
... and so on for coast, dune, eye, host, raiser, shaper, silence, snout, spire, tide, ward, wayfinder, bolt, flow
```

#### Code Implementation
```java
public ExampleArmorRenderer() {
    super(AzArmorRendererConfig.builder(GEO, TEX)
        .addRenderLayer(new AzArmorTrimLayer(
            Identifier.fromNamespaceAndPath(YOUR_MOD_ID, "trims/your_armor")
            // supportPatterns defaults to true: "trims/your_armor" + "_" + pattern
        ))
        .build());
}
```

## Advanced Usage

### Custom Texture Choice
Pass a function to pick the texture for each trim yourself. It's still colored with the trim material's palette:
```java
.addRenderLayer(new AzArmorTrimLayer(
    trim -> Identifier.fromNamespaceAndPath(
        YOUR_MOD_ID,
        "trims/custom_" + trim.pattern().value().assetId().getPath()
    )
))
```

### Custom Palettes
A second function picks the palette. This is how you reproduce vanilla's darker trims, where a trim on armor of the same material (e.g. a gold trim on gold armor) uses a darker palette so it stays visible:
```java
.addRenderLayer(new AzArmorTrimLayer(
    trim -> Identifier.fromNamespaceAndPath(YOUR_MOD_ID, "trims/your_armor_trim"),
    trim -> trim.material().is(TrimMaterials.GOLD)
        ? TrimMaterials.Palette.GOLD_DARKER.id()
        : AzArmorTrimLayer.MATERIAL_PALETTE.apply(trim)
))
```
- `TrimMaterials.Palette` has an id for every vanilla palette. Darker variants exist for iron, netherite, copper, gold and diamond (`IRON_DARKER`, `NETHERITE_DARKER`, `COPPER_DARKER`, `GOLD_DARKER`, `DIAMOND_DARKER`).
- Palette ids are relative to `textures/palettes/`: `TrimMaterials.Palette.GOLD_DARKER.id()` is `minecraft:trim/gold_darker`, which is `assets/minecraft/textures/palettes/trim/gold_darker.png`. A mod's own palette works the same way under its namespace.

## Updating from 1.21.x

- **Delete `assets/minecraft/atlases/armor_trims.json`.** Minecraft no longer uses it.
- **Add a `.png.mcmeta`** with the `palette` section to each trim texture.
- **Texture ids no longer point into the atlas.** Use a path relative to `textures/`, e.g. `yourmod:trims/your_armor_trim` instead of `yourmod:armor/trim/your_armor_trim`. The texture files can stay where they are if you point the id at them.
- **Custom texture functions return only the texture.** They no longer append the material name (`_gold`, `_iron`, ...), because the material color now comes from the palette. Darker variants move to a palette function, see [Custom Palettes](#custom-palettes).
- **`ResourceLocation` is now `Identifier`.**

## Important Notes

- **Custom Textures Required**: Vanilla trim textures are made for the vanilla armor model's UV layout, so they won't line up with custom armor models.
- **Same Size as the Armor Texture**: The trim texture uses your armor model's UVs.
- **Palette Metadata Required**: Without the `.png.mcmeta` palette section, the texture can't be recolored and the trim won't show correctly.

## Troubleshooting

### Trims Not Appearing
- Check that the texture id matches the file: relative to `textures/`, no `.png`.
- Check that the `.png.mcmeta` sits next to the texture and contains the `palette` section.
- Ensure you're testing with items that have a trim applied.

### Wrong Colors
- Check that your texture uses the gray shades of vanilla's `trim_base` palette. Shades not in the palette won't be recolored.

### Trim Misaligned
- Make sure the trim texture is the same size as the armor texture and drawn on the same UV layout.
