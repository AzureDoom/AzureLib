# How to animate Armor

## Creating your custom AzItemAnimator

For this, you will create a class which extends `AzItemAnimator`. This class will handle the registration of animation controllers and providing the animation file's location for the animations.

Example:
```java
public class ExampleArmorAnimator extends AzItemAnimator {
    private static final ResourceLocation ANIMATIONS = new ResourceLocation(
        YOUR_MOD_ID,
        "animations/item/examplearmor.animation.json"
    );

    @Override
    public void registerControllers(AzAnimationControllerContainer<ItemStack> animationControllerContainer) {
        animationControllerContainer.add(
            AzAnimationController.builder(this, "base_controller")
                .build()
        );
    }

    @Override
    public @Nonnull ResourceLocation getAnimationLocation(ItemStack animatable) {
        return ANIMATIONS;
    }
}
```

Some highlights of the above example.

- `ANIMATIONS`:
This stores the `ResourceLocation` reference to the animation JSON file. You need to replace `YOUR_MOD_ID` with your mod's ID and ensure the file path matches your JSON animation file.

- `registerControllers()`
Registers the animation controllers that will define the animation behavior and states for the item. You can multiple if needed.

## Creating an Animation Dispatcher

<Callout variant="info">
    You can find more about [AzCommands here](../misc/animating/azcommands_101)
</Callout>

This class isn't required but is highly suggested to help store your animation commands to call in other classes.

Example:
```java
public class ExampleArmorDispatcher {
    private static final AzCommand EQUIP_COMMAND = AzCommand.create(
        "base_controller",
        "equipping",
        AzPlayBehaviors.PLAY_ONCE
    );

    private static final AzCommand IDLE_COMMAND = AzCommand.create(
        "base_controller",
        "idle",
        AzPlayBehaviors.LOOP
    );

    public void equip(Entity entity, ItemStack itemStack) {
        EQUIP_COMMAND.sendForItem(entity, itemStack);
    }

    public void idle(Entity entity, ItemStack itemStack) {
        IDLE_COMMAND.sendForItem(entity, itemStack);
    }
}
```

## Accessing your Dispatcher to trigger animations

You will now define your ExampleArmorDispatcher from above in your ArmorItem class.

Example:
```java
public class ExampleArmor extends ArmorItem {
    // This is your class where you will setup the AzCommands/Animations you wish to play
    public final ExampleArmorDispatcher dispatcher;

    /**
     * @param armorType 0 helmet, 1 chestplate, 2 leggings, 3 boots
     */
    public ExampleArmor(int id, int armorType) {
        // Beta 1.7.3 armor: (item ID, protection level, armor texture, slot); 3 is diamond.
        // The armor texture (0 cloth, 1 chain, 2 iron, 3 diamond, 4 gold) only matters to vanilla's armor renderer.
        super(id, 3, 3, armorType);
        // Create the instance of the class here to use later.
        this.dispatcher = new ExampleArmorDispatcher();
    }
}
```

Now you can call your dispatcher to trigger different animations. Beta 1.7.3 has no armor tick hook, so for an idle animation that should play all the time, add a small method to your armor:

```java
    public void armorTick(PlayerEntity player, ItemStack itemStack) {
        if (!Mc.isClientSide(Mc.world(player))) {
            dispatcher.idle(player, itemStack);
        }
    }
```

and call it every tick for worn pieces from a mixin into `PlayerEntity#tick`:

```java
@Mixin(PlayerEntity.class)
public abstract class PlayerEntityMixin_ArmorTick {

    @Inject(method = "tick", at = @At("TAIL"))
    private void yourmod$armorTick(CallbackInfo ci) {
        PlayerEntity player = (PlayerEntity) (Object) this;
        // Beta 1.7.3's armor slots: 0 boots, 1 leggings, 2 chestplate, 3 helmet.
        for (int i = 0; i < 4; i++) {
            ItemStack stack = Mc.armor(player, i);
            if (stack != null && Mc.item(stack) instanceof ExampleArmor) {
                ((ExampleArmor) Mc.item(stack)).armorTick(player, stack);
            }
        }
    }
}
```

## Creating your Renderer

This renderer is responsible for how your armor is displayed in the game.

It connects the armor with the following:
1. **Geometry file (`geo.json`)**: Defines the 3D model of the armor.
2. **Texture file (`.png`)**: The visual appearance of the armor (applies over the geometry).
3. **Animator**: Animations for the armor, provided by `ExampleArmorAnimator`.

<Callout variant="info">
    See [AzRendererConfigs 101](../misc/rendering/azrenderer_config#azarmorrendererconfig) for all AzArmorRendererConfig#builder options.
</Callout>

```java
public class ExampleArmorRenderer extends AzArmorRenderer {
    private static final ResourceLocation GEO = new ResourceLocation(
        YOUR_MOD_ID,
        "geo/item/examplearmor.geo.json"
    );

    private static final ResourceLocation TEX = new ResourceLocation(
        YOUR_MOD_ID,
        "textures/item/examplearmor.png"
    );

    public ExampleArmorRenderer() {
        super(
            AzArmorRendererConfig.builder(GEO, TEX)
                .setAnimatorProvider(ExampleArmorAnimator::new)
                .build()
        );
    }
}
```

## Registering your Renderer

Call `AzArmorRendererRegistry#register()` on the client, once your items exist: from an OSL `ItemEvents.REGISTER_ITEMS` listener you add in your `client-init` entrypoint (see [Where to register things](../_homepage#where-to-register-things)).

```java
private static void registerItemRenderers() {
    AzArmorRendererRegistry.register(ExampleArmorRenderer::new, YourItemRegistry.YOUR_ARMOR_HELMET,
            YourItemRegistry.YOUR_ARMOR_CHESTPLATE,
            YourItemRegistry.YOUR_ARMOR_LEGGINGS,
            YourItemRegistry.YOUR_ARMOR_BOOTS);
}
```

<Callout variant="info">
    Beta 1.7.3 has no armor model hook, so AzureLib draws registered armor from a mixin into the player renderer's armor passes, in place of the vanilla armor model. Armor items must extend Beta 1.7.3's `ArmorItem`, because Beta 1.7.3 only renders armor passes for armor items. You can also register vanilla armor (for example `Item.DIAMOND_HELMET`) to replace its look.

    For the inventory icon, register a 16x16 PNG with `AzItemIcons.register(item, new ResourceLocation("yourmodid", "textures/item/example_helmet.png"))` in the same client listener; see [Item Icons, Names and Sounds](../misc/icons_and_lang#item-icons). This also works for vanilla armor you replace.
</Callout>

## Registering your Armor for proper animation triggering

To ensure trigger animations work properly, you will need to also call `AzIdentityRegistry#register()` on both the client and the server, after your items are created, for example at the end of your OSL `ItemEvents.REGISTER_ITEMS` listener (subscribed from your common `init` entrypoint).

```java
public static void register() {
    // ... create your armor with Item.AUTO_ASSIGN_ID and register it with OSL's ItemRegistry ...
    AzIdentityRegistry.register(YourItemRegistry.YOUR_ARMOR_HELMET,
            YourItemRegistry.YOUR_ARMOR_CHESTPLATE,
            YourItemRegistry.YOUR_ARMOR_LEGGINGS,
            YourItemRegistry.YOUR_ARMOR_BOOTS,
            ...);
}
```
