## Creating your Renderer

This renderer is responsible for how your custom item is displayed in the game.

It connects the item with the following:
1. **Geometry file (`geo.json`)**: Defines the 3D model of the item.
2. **Texture file (`.png`)**: The visual appearance of the item (applies over the geometry).

<Callout variant="info">
    See [AzRendererConfigs 101](../misc/rendering/azrenderer_config#azitemrendererconfig) for all AzItemRendererConfig#builder options.
</Callout>
<Callout variant="warning">
    There is currently a bug in the plugin which exports the displays with an offset applied, please use useNewOffset(true) in your AzItemRendererConfig builder to fix this.
</Callout>

```java
public class ExampleItemRenderer extends AzItemRenderer {
    private static final ResourceLocation GEO = new ResourceLocation(
        YOUR_MOD_ID,
        "geo/item/exampleitem.geo.json"
    );

    private static final ResourceLocation TEX = new ResourceLocation(
        YOUR_MOD_ID,
        "textures/item/exampleitem.png"
    );

    public ExampleItemRenderer() {
        super(
            AzItemRendererConfig.builder(GEO, TEX).build()
        );
    }
}
```

## Registering your Renderer

Call `AzItemRendererRegistry#register()` on the client, once your items exist: from an OSL `ItemEvents.REGISTER_ITEMS` listener you add in your `client-init` entrypoint (see [Where to register things](../_homepage#where-to-register-things)). AzureLib then draws the item everywhere: in the GUI, in first and third person, and on the ground.

AzureLib can't look up a Beta 1.7.3 item's Blockbench-exported item model (with its `display` transforms) by registry name the way it does on other versions. Pass its location when you register:

```java
private static void registerItemRenderers() {
    AzItemRendererRegistry.register(
        YourItemRegistry.YOUR_ITEM,
        new ResourceLocation(YOUR_MOD_ID, "models/item/exampleitem.json"),
        ExampleItemRenderer::new
    );
}
```

Only the `display` block of that file is used; the parent is ignored. `AzItemRendererRegistry.register(ExampleItemRenderer::new, YourItemRegistry.YOUR_ITEM)` also works if you don't need display transforms.

```json
// assets/yourmodid/models/item/exampleitem.json
{
  "parent": "builtin/entity",
  "display": {
    // display transforms exported from Blockbench
  }
}
```

<Callout variant="info">
    Beta 1.7.3 only distinguishes four contexts, which AzureLib maps to `GUI`, `GROUND`, `FIRST_PERSON_RIGHT_HAND` and `THIRD_PERSON_RIGHT_HAND`. If an item sits wrong in one of them, override `AzItemRenderer#applyBaseTransform`.
</Callout>

<Callout variant="info">
    Mod blocks don't get a block item of their own on Beta, so place an AzureLib-rendered block with a plain item of your own and register the renderer for that item (see [Block Entities](../blockentities/blockentities)).
</Callout>

To keep a flat sprite in one context while AzureLib draws the model everywhere else, use `useVanillaRenderingIn` on the config builder, for example `.useVanillaRenderingIn(AzItemDisplayContext.GUI)` together with an item icon from [`AzItemIcons`](../misc/icons_and_lang#item-icons).
