## Creating your Renderer

This renderer is responsible for how your custom item is displayed in the game.

It connects the item with the following:
1. **Geometry file (`geo.json`)**: Defines the 3D model of the item.
2. **Texture file (`.png`)**: The visual appearance of the item (applies over the geometry).

<Callout variant="info">
    See [AzRendererConfigs 101](../misc/rendering/azrenderer_config#azitemrendererconfig) for all AzItemRendererConfig#builder options.
</Callout>
<Callout variant="warning">
    There is currently a bug in the plugin which exports the displays with an offset applied, please use useNewOffset(true) in your AzItemRendererConfig builder to fix this.
</Callout>

```java
public class ExampleItemRenderer extends AzItemRenderer {
    private static final ResourceLocation GEO = new ResourceLocation(
        YOUR_MOD_ID,
        "geo/item/exampleitem.geo.json"
    );

    private static final ResourceLocation TEX = new ResourceLocation(
        YOUR_MOD_ID,
        "textures/item/exampleitem.png"
    );

    public ExampleItemRenderer() {
        super(
            AzItemRendererConfig.builder(GEO, TEX).build()
        );
    }
}
```

## Registering your Renderer

Call `AzItemRendererRegistry#register()` on the client during `FMLInitializationEvent`, for example from your client proxy's `init` method. On 1.7.10 this also registers a Forge `IItemRenderer` for the item, so AzureLib draws it everywhere: in the GUI, in first and third person, and on the ground.

```java
// ClientProxy
@Override
public void init() {
    AzItemRendererRegistry.register(ExampleItemRenderer::new, YourItemRegistry.YOUR_ITEM);
}
```

1.7.10 has no json item models, but AzureLib still reads the `display` transforms from the Blockbench-exported item model, `assets/<modid>/models/item/<registry name>.json`, and applies them like later versions do. Only the `display` block is used; the parent is ignored.

```json
// assets/yourmodid/models/item/exampleitem.json
{
  "parent": "builtin/entity",
  "display": {
    // display transforms exported from Blockbench
  }
}
```

<Callout variant="info">
    1.7.10 only distinguishes four contexts, which AzureLib maps to `GUI`, `GROUND`, `FIRST_PERSON_RIGHT_HAND` and `THIRD_PERSON_RIGHT_HAND`. If an item sits wrong in one of them, override `AzItemRenderer#applyBaseTransform`.
</Callout>
